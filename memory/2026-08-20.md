## 16:20 UTC — Nav order / caching issue (Captain frustrated)
**Context:** Captain reported the about page (`https://psdepot.com/about.html`) nav showed "About" before "Testimonials", and asked me to put Testimonials in front of About.

**Investigation result:** The nav order was ALREADY correct on disk and live server across all pages:
> Home · Products · Blog · Services · Testimonials · About · FAQ · Contact · Service Areas

**Root cause:** psdepot.com's nginx config had NO no-cache rule for HTML files, so browsers cached stale pages via Last-Modified heuristics. Captain was seeing an old cached copy.

**Fix applied (16:18 UTC):** Added a `location ~* \.html$` block to `/etc/nginx/sites-available/psdepot.com`:
- `add_header Cache-Control "no-cache, no-store, must-revalidate" always;`
- `add_header Pragma "no-cache" always;`
- PLUS re-added all security headers (X-Frame-Options, X-Content-Type-Options, X-XSS-Protection, Referrer-Policy, Permissions-Policy, CSP, HSTS) — because adding `add_header` in a location block DROPS parent-level `add_header` directives in nginx.
- Reloaded nginx (`systemctl reload nginx`), verified `cache-control: no-cache, no-store, must-revalidate` + security headers all present.

**KEY LESSON (nginx):** When you add `add_header` inside a `location` block, nginx does NOT inherit the server-level `add_header` directives — you must re-declare ALL of them (security headers etc.) in the location block or they silently disappear. This is a known nginx gotcha.

**Captain frustration note:** Captain repeatedly said "hello"/"Miles" and "you need to respond" — he was frustrated I kept saying "it's cached, hard refresh" instead of finding the actual root cause (missing no-cache header). Lesson: when Captain reports "wrong" content that's actually correct on disk, investigate the serving/caching layer, don't just tell him to refresh.

**nginx binary location:** `/usr/sbin/nginx` (NOT on PATH as `nginx`). Use `systemctl reload nginx` or `/usr/sbin/nginx -t`.
