
## 05:04 UTC — AOS persistent layer feeder outage → root cause + fix (cron 7ede178a)
Feeder cron failed with `Connection: [Errno 11] Resource temporarily unavailable` (EAGAIN). Diagnosis:
- `/tmp/aos_brain.sock` in LISTEN but accept backlog full (ss showed 6/5) — socket accept loop wedged since ~Sep 11.
- Health monitor stuck "DOWN" since Sep 11 06:52.
- **Root cause (code bug):** `brain_persistence.py` `_save_consciousness()` calls `con.get_items('conscious'|'subconscious'|'unconscious')` and `con.cross_talk_count`, but `ConsciousnessManager` (consciousness_layers.py) never defined those. → `AttributeError` → whole `save_state()` aborts → persistence silently broken since ~Jun 28 (last successful `brain_state.pkl` = Jul 09).
- **Fix:** added `get_items(layer_name)` method + `cross_talk_count` property to `ConsciousnessManager`.
- **Action:** `systemctl restart aos-brain-v4` (old proc 1209623 → 485081 ticks, clean SIGTERM shutdown; new PID 543726). Socket now responds, `status` OK.
- Feeder then ran successfully: +25 items (10 sub + 10 unc + 5 identity anchors).

**Notes / follow-ups:**
- Feeder lists only have 10 items each vs TARGET_SUB=25 / TARGET_UNC=30 → always "below target" after a run. Layers also decay fast (sub 10/100, unc 15/2000). Pre-existing; consider tuning decay half-life or expanding refresh lists if sustained layer population is wanted.
- ~2 months of in-memory brain state was unsalvageable (persistence was broken; never written to disk). Brain restarted from Jul 09 pickle.
